26  Testing

import sandbox_widget

This chapter is about how you figure out if your code solves the problem the way you intended. You will be surprised how often that is not the case, even for seasoned programmers. There are many good reasons to to test your code. The three most important ones are:

Makes you think: Testing forces you to slow down and think about exactly what the code you want to write is supposed to do. Writing tests before you start writing the actual code, helps you anticipate errors and corner cases that need to be addressed in the way you implement your solution.

Gives you peace of mind: Testing allows you to trust that a function you have written actually works as it is supposed to. That frees up your mind to focus on about how to use it as a component in solving the larger, more complicated problem.

Makes you trust code from an AI: When it comes to code you did not write yourself, the only way to really know if you can trust it, is to write your own tests for the code and/or to read any tests the AI wrote.

assert means “make sure”

Testing can be done and organized in many different ways, but always boils down to to “making sure” that something is as you expect. In Python, “making sure” is called assert. E.g., to make sure your function variable x is larger than zero, you simply write assert x > 0. Let’s take as an example the function below that splits an open reading frame into a list of codons:

def split_orf(orf):
    codons = []
    for i in range(0, len(orf)-3+1, 3):
        codon = orf[i:i+3]
        codons.append(codon)
    return codons

split_orf('ATGCCATAATGA')

You can add an assert statement inside the function for each thing you want to “make sure” of. Be creative, think of as many things to check as you can. Here are some:

def split_orf(orf):    
    codons = []
    for i in range(0, len(orf)-3+1, 3):
        assert i < len(orf)
        codon = orf[i:i+3]
        assert len(codon) == 3
        codons.append(codon)
    assert len(orf) == 3 * len(codons) # check codon list has the right length
    return codons

split_orf('ATGCCATAATGA')

The project testing utility

To keep you focused on the programming part, each of the programming projects you will do in this course comes with a ready-made suite of tests of the functions you are asked to implement. So, for each function, you can run tests to ensure it implements the behavior it is supposed to.

Each project comes with two files that you can download from the course page. They have their names for a good reason, so do not change them. In the first project about translating DNA, they are called translationproject.py and test_translationproject.py.

To be able to test your functions, you must write your code in the file called translationproject.py. To run your code, you type this in the Terminal as usual:

Terminal
python translationproject.py

To test the functions as you complete each one, you can run the test script test_translationproject.py like this:

Terminal
python test_translationproject.py

The code in test_translationproject.py reads your code in translationproject.py and performs a series of tests of each function. When you run the test script, four things may happen depending on the state of your code:

Case 1: If you have not yet implemented all the functions, the test script will remind you (once for each test) that you did not implement the functions with the names required.

Terminal
*********************************************************
ATTENTION! The following functions are not defined:

    translate_codon
    split_codons
    translate_orf

These functions are either not correctly named (spelled)
or not defined at all. They will be marked as FAILED.
Check your spelling if this is not what you intend.
*********************************************************

Ran 16 tests in 0.000s

OK (skipped=14)

If you have implemented a function but misspelled its name, you will also get this type of reminder. The reminders are meant to ensure that you do not hand in the assignment with missing or misspelled function definitions.

Case 2: If a test for one of the functions you have written fails, the testing is aborted, and the script prints some information to help you understand what the problem could be. Say you wrote the function translate_codon wrongly so that it always returns M for some reason:

def translate_codon(codon):
    return 'M' # crazy

then you would get this message:

FAILED (failures=1)
